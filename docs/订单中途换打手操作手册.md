# 订单中途换打手操作手册

## 功能说明

“中途换人”位于订单列表“转单”弹窗内，与原“转单”流程分开。中途换人不改变旧转单行为，调用 `POST /api/admin/orders/{id}/mid-replace`，不会扣款或立即结算。

## 使用条件

仅对后端 `canMidReplace` 返回 `true` 的订单开放。不可操作时，页面提示后端返回的 `midReplaceBlockReason`。资格判断以该字段为准，不使用分润展示金额推断。

接口适用于进行中、单人、非代练通且有当前接单打手的订单；具体校验仍以服务端为准。换人后至完单前禁止修改平台/俱乐部加减价。

## 操作步骤

1. 进入“订单管理 > 订单列表”，点击进行中订单的“转单”。
2. 在弹窗顶部切换到“中途换人”。弹窗会显示当前打手及当前剩余打手可得金额。
3. 输入原打手本段“已完成金额”。金额需大于 0、最多两位小数，并且必须**小于**当前剩余打手可得金额。
4. 选择换人方式：
   - **人工派单**：先选俱乐部，再选接手打手；提交时发送 `mode=ASSIGN` 和 `targetPlayerId`，允许跨俱乐部指定。
   - **放入大厅**：提交时发送 `mode=HALL`，固定进入公共抢单大厅，不需要选择大厅范围。
   - **代练通**：填写代练通订单号和派单价格，可填写备注；派单价格需大于 0，且不超过订单金额加平台加减价。提交时发送 `mode=DAILIANTONG`、`dltOrderNo`、`dltDispatchPrice` 和非空备注。
5. 确认后，成功提示并刷新订单列表。服务端返回的订单详情包含换人状态和剩余金额等信息。

## 提交参数

所有方式都提交 `completedAmount` 和 `mode`。人工派单额外提交 `targetPlayerId`；代练通额外提交 `dltOrderNo`、`dltDispatchPrice`，备注可选。放入大厅不传 `hallScope`。凭证 `evidenceUrl` 为可选字段，当前页面未提供上传入口。

已完成金额上限使用当前剩余打手可得金额：首次换人优先使用 `midReplacePoolAmount`，否则使用详情中的打手到手金额；再次换人使用 `midReplaceRemainAmount`。前端校验仅用于提示，最终资格和金额校验由服务端执行。

## 结算说明

已完成金额先记录为待结算份额，不会在换人时入账。订单完单审核后，待结算份额与当前接手人的剩余金额统一分账、使用同一账期。改派代练通时，剩余打手池不再分给接手人。订单关闭、全额退款或渠道关闭时，相关份额作废。最终以服务端结算结果为准。

## 与旧转单的区别

旧“转单”继续调用原 `POST /api/admin/orders/{id}/transfer`，原有扣款和流程保持不变；“中途换人”保持订单进行中、保留分润锁，不立即扣款或入账。
