# 订单相关审批功能说明

## 功能范围

订单编辑申请、订单作废申请和管理员审批均已接入后端接口。申请状态由订单接口返回，审批列表和审批操作由服务端持久化。

## 编辑申请

- 编辑弹窗仅当 `manualCreated=true` 且 `canApplyEdit=true` 时显示“申请编辑”。
- 申请内容为游戏名称、游戏规格、购买项目和订单金额；提交前二次确认。
- 接口：`POST /api/admin/orders/{id}/approvals/edit`
- 请求体：`{ gameId, specId, itemName, amount }`
- 提交后使用 `editApprovalStatus` 显示“审批中”“已同意”或“已驳回”；每单仅申请一次，包含已驳回申请。
- `canApplyEdit=false` 时不再显示申请按钮。审批同意后的修改由后端执行。

## 作废申请

- 订单列表根据 `canApplyVoid` 显示“作废”操作；提交前二次确认。
- 接口：`POST /api/admin/orders/{id}/approvals/void`，`reason` 可选。
- 提交后根据订单数据中的 `voidApprovalStatus` 显示审批状态，并隐藏重复申请入口。
- 管理员同意后的全额退款与关单由后端完成。

## 管理员审批

- “订单相关审批”菜单仅管理员可见。
- 列表接口：`GET /api/admin/orders/approvals`
- 支持 `type`（`SPEC_EDIT` / `VOID`）、`status`（`PENDING` / `APPROVED` / `REJECTED`）、`from`、`to`、`page`、`pageSize`。
- 列表展示事项、订单信息、申请人、时间和状态；仅待审批项显示操作按钮。
- 同意：`POST /api/admin/orders/approvals/{approvalId}/approve`
- 驳回：`POST /api/admin/orders/approvals/{approvalId}/reject`
- 同意和驳回操作前均需二次确认；驳回不要求原因。

## 订单数据字段

订单列表和详情需返回 `manualCreated`、`canApplyEdit`、`editApprovalStatus`、`editApprovalId`、`canApplyVoid`、`voidApprovalStatus`、`voidApprovalId`。
